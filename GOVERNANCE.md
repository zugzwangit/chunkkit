# Governance

ChunkKit uses a maintainer-led, consensus-seeking model.

- Maintainers review releases, security reports, compatibility decisions, and first-party plugins.
- Contributors earn maintainer status through sustained technical and community contributions.
- Breaking public API or schema changes require an RFC in GitHub Discussions and an architecture
  decision record.
- Routine fixes and backward-compatible features use normal pull-request review.
- Security maintainers may privately prepare and release urgent fixes.

The initial maintainer list lives in `CODEOWNERS`. Changes require approval from two maintainers once
the project has at least three maintainers. The project uses DCO sign-off and does not require a CLA.
